    For IT and security teams: what phiward runs on a Mac¶

    • For: the people who run an endpoint tool on Macs where phiward is used.
    • You will have: every process phiward starts, with its exact command line and a regex for it, so that you can recognise each one and, if your policy needs it, scope one exception.

    What phiward is¶

    phiward keeps protected health information (PHI) out of what an AI coding agent sends to its model provider. It runs the agent's commands in a kernel profile (sandbox-exec) and masks the output. It is a Python package that runs as the user.

    It needs no admin rights, no kernel extension and no network service. It opens no listening port: the agent and the broker talk through files in a private folder.

    What it installs and writes¶

    All of it is in the user's home folder, written by the user's own account:

    • The package, installed by uv tool or pipx, with its own Python: for example ~/.local/share/uv/tools/phiward/ (uv) or ~/.local/pipx/venvs/phiward/ (pipx). Below it, lib/python3.X/site-packages/phiward/ holds phiward's code and its two hook files (data/clean-exec.sh, data/clean-env.awk).
    • The launcher ~/.local/bin/phiward: a Python script that uv or pipx writes.
    • phiward's own state in ~/.phiward/: the sessions of phiward launch, the kernel profiles of running commands (profiles/, one file per command, removed when it ends), records of running launchers, the broker's status and backups.
    • The spool ~/.phiward-spool/: requests from the agent to the broker, and their output.
    • Scratch folders in ~/.cache/phiward/: one per gateway command, removed when it ends.
    • The user config ~/.config/phiward/config.toml, and ~/.config/phiward/claude-settings.json.
    • Claude Code's settings ~/.claude/settings.json: the hook entries and the sandbox settings.
    • The login service ~/Library/LaunchAgents/org.phiward.broker.plist, if the user sets it up, and its log ~/Library/Logs/phiward/broker.log.
    • In a repository, on request: .claude/settings.json (install --project) and the git hooks .git/hooks/pre-commit and pre-push (phiward init).
    • The Claude Code plugin, if the user installs it: Claude Code copies it into its own plugin folder (~/.claude/plugins/...).

    Every process phiward starts on macOS¶

    Each row is one kind of process. The ID points to its command lines and its regex in the list below. phiward puts no code in a local command line: no python -c, no sh -c of its own, no awk program, no sandbox-exec -p. There are two exceptions:

    • the command that ssh carries to the remote host (C3, C7, C8), which runs there, not on the Mac. A push's (C7) is a fixed sh -c script with the destination path;
    • the project hook's fixed line (R1, R2), which a repository commits.

    G2 phiward doctor /usr/bin/sandbox-exec each doctor the gateway's self-test: /usr/bin/true in the profile
    C1 the broker /usr/bin/sandbox-exec each local phiward copy makes the destination folder (/bin/mkdir)
    C2 the broker /usr/bin/sandbox-exec each local phiward copy copies the files (/usr/bin/rsync)

    P2 the P1 script /usr/bin/awk with each P1 the plugin's copy of H2

    P4 Claude Code the Python once per session, with the plugin phiward's MCP server (the gateway's tools)

    L3 Claude Code, under launch the Python each tool call and prompt the hook in a launched session
    L4 launch, a wrapped server, doctor, the session note the Python each start phiward checks its own installed files, in a separate Python

    M1 Claude Code the Python once per session, per wrapped MCP server starts a wrapped MCP server under phiward launch
    M2 phiward launch (exec) the server's inside a launched session a wrapped server inside a session: its own command line, unchanged
    S1 launchd the Python at login, kept running the broker
    S2 phiward setup, phiward broker --service --write /bin/launchctl when the user sets up the login service loads or restarts the broker's service
    D1 phiward install the Python each install --write checks that the isolated Python finds phiward
    D2 phiward doctor /bin/sh each doctor runs the H1 script once, with phiward --help
    D3 the D2 script (exec) the Python with each D2 phiward --help, through the launcher
    R1 Claude Code /bin/sh each tool call, prompt and session start, in a repository with install --project the project hook: one fixed line
    R2 the R1 line /usr/bin/awk with each R1 lists the variables to clear (its program is in the fixed line)
    R3 git /bin/sh each commit and push, in a repository with phiward init the git hooks phiward writes
    R4 the R3 hook (exec) the Python with each R3 phiward's git checks
    R5 R4 git from PATH with each R4 the git commands of those checks

    "The Python" is phiward's own Python: the bin/python of its uv or pipx environment, which points to the Python that uv or the system installed. "The launcher" is ~/.local/bin/phiward, a Python script; the kernel shows it as <python> <launcher>.

    The user also starts phiward in a terminal (phiward launch -- claude, phiward doctor, phiward setup). Those command lines are the user's own words after <python> <launcher>.

    Rarer forms, not in the list: a local copy without rsync runs /bin/cp -R -n -- SOURCE... DEST; a dry run runs /usr/bin/true; a git hook without phiward on PATH runs python3 -m phiward git-hook NAME; phiward run --remote runs /usr/bin/sandbox-exec -f <profile> /usr/bin/ssh ... HOST -- WORDS (the C3 or C8 ssh words), where WORDS are the agent's own, quoted for the remote shell.

    G1 and L1 match any command under any file in ~/.phiward/profiles. The account that runs phiward can write that folder, so a process of that account could start sandbox-exec there with a profile of its own, (allow default) included. An exception for G1 or L1 trusts every process of that account to that extent.

    The command lines¶

    Each entry gives the command line as the kernel shows it (argv), and a regex for it (regex; - where none fits). The regexes are written for an install by uv or pipx. The placeholders:

    • <python>: phiward's Python, such as ~/.local/share/uv/tools/phiward/bin/python;
    • <PKG>: its site-packages folder; <plugin>: the plugin's folder;
    • <launcher>: ~/.local/bin/phiward;
    • <profile>: ~/.phiward/profiles/ and a random name of 32 hex digits, then .sb;
    • <home>: the home folder; <uid>: the user's id; <entry>: 16 hex digits;
    • <path>, <source>, <dest>: paths the request names;
    • <ssh-config>, <socket>, <host>: the user's ssh config file, the shared connection's socket and the host;
    • <remote-pull>: the command for the remote host on a pull, tar -c -f - -C DIR -- NAME (or -C DIR .); <remote-push>: on a push, sh -c SCRIPT sh DIR, where SCRIPT is the fixed text _RECEIVE in remote.py;
    • <record>: the package's install record; <claude>: Claude Code's program;
    • <command> ..., <tool> ..., <server> ..., <arguments>: the user's or the agent's own words;
    • <project-hook>, <project-prompt-hook>, <project-note>: the project hook's fixed text (PROJECT_HOOK, PROJECT_PROMPT_HOOK and PROJECT_NOTE in install.py), which begins command -v phiward >/dev/null 2>&1 ||; <awk-program>: the awk program in it, which begins BEGIN{for(k in ENVIRON).

    A path with a space in it shows as more than one word, so [^ ]+ does not match it. Use .+ there if your users have such paths.

    Who signed what¶

    sandbox-exec, sh, awk, ssh, mkdir, rsync, getconf and launchctl are Apple's platform binaries. The Python is the one the user installed, signed by whoever built it (the python.org installer's is signed with its Developer ID). git is Apple's, or the one the user installed (Homebrew, for example). phiward itself is not signed code: it is Python source that the Python reads.

    What the agent runs is not phiward's¶

    The agent chooses the commands it runs through the gateway (G1) and inside a launched session (L1). Their command lines are the agent's own, and they may use any shape: an agent may run python -c or sh -c there. Their parent is sandbox-exec, and they run inside phiward's profile. A wrapped MCP server (M1, M2) has the command line its user configured; many servers are started as sh -c "..." or npx ....

    What to put in an exception¶

    If your policy needs an exception, scope it narrowly:

    • by the image path and the regex of the row you see;
    • to the users who run phiward;
    • not for all of Python, and not for every program in phiward's Python folder.

    The rows that phiward starts most often are H1 to H3 (each tool call in a Claude Code session), L3 (each tool call under launch) and G1 (each gateway request).

    How to check a Mac¶

    phiward doctor, in the user's terminal, checks the install, the hook wiring, the broker and the gateway's profile, and says what is missing. It starts G2, D2, L4 and L5.

    Limits¶

    • sandbox-exec is deprecated by Apple, with no date and no named replacement.
    • The commands the agent runs (G1, L1) have their own shapes, and your tool may judge what they do. phiward cannot change that.
    • The project hook (R1, R2) is one fixed line with code in it. A repository commits it, and the same line runs on Linux. A push's remote command (C7) is fixed code too, carried to the remote host.
    • C3, C7 and C8 have no regex either. phiward's fixed ssh options do not fit in 256 characters, and a regex that loops over options would admit one that weakens them (ssh takes the first value it sees). Match these rows on the image path /usr/bin/ssh with its parent /usr/bin/sandbox-exec, and on the fixed options exactly, in the order the shape gives them; the profile file, the ssh config, the socket, the host and the paths vary.
    • R1, R2 and C7 have no regex. Their full text is longer than 256 characters, and a regex for its first part would also admit that text with any command after it. If you need an exception for them, match the exact command line instead: R1 and R2 are the same on every Mac (a hash of the command line works), and C7 is the fixed text with the user's paths (receive_script in remote.py builds it).
    • This page lists macOS only.

    Linux¶

    On Linux phiward confines with bubblewrap (bwrap), Landlock and seccomp instead of sandbox-exec. Its processes have the same parents and the same jobs, with other command lines: bwrap in place of sandbox-exec, a small Python helper with inline code inside the bwrap profile, and systemctl --user for the login service. Those command lines are not listed here.
